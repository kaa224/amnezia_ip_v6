# 1. Требования и переменные

Предпочтителен отдельный стенд: два Linux VPS с публичными IPv4 и маршрутизируемыми IPv6, TUN, systemd, iproute2, iptables/ip6tables одной реализации и conntrack. Базовый ориентир — поддерживаемые Debian 12/13 или Ubuntu 24.04 LTS, amd64/arm64. Это целевые платформы, не матрица реально пройденных испытаний. 1–2 vCPU, 1 GiB RAM и несколько GiB диска — ориентир для персонального использования, не гарантия скорости. Сборку выполняйте отдельно: она требует больше памяти, Go, C toolchain для tools, а при сборке Realm — Rust. Контейнер с доступом только к своей сети не заменяет обследование хоста.

Уточните правила провайдера, квоты трафика, доступность UDP, IPv6 MTU и консоль восстановления. Userspace AWG не требует замены ядра, DKMS или перезагрузки. Docker не требуется. На уже занятом VPS любое включение IPv4 forwarding и интеграция firewall требуют отдельного анализа; этот проект не меняет существующие сети.

## Пример плана

Все адреса ниже непригодны для реального Интернета, включая внутренние адреса.

| Переменная | Пример | Назначение |
|---|---|---|
| EXIT4 | 192.0.2.10 | Публичный IPv4 выходного VPS |
| EXIT6 | 2001:db8:10::10 | Публичный IPv6 выходного VPS |
| RELAY4 | 198.51.100.20 | Публичный IPv4 входного VPS |
| RELAY6 | 2001:db8:20::20 | Источник межсерверного транспорта |
| WAN_IF | REPLACE_WAN_IF | Фактический интерфейс выхода |
| Direct | 52010/udp, awg31d | Клиент → EXIT4 |
| Relay backend | 52011/udp, awg31r | Только RELAY6 → EXIT6 |
| Realm frontend | 52012/udp | Клиент → RELAY4 |
| Direct LAN | 203.0.113.0/26, 2001:db8:31:1::/64 | Сервер .1 / ::1, Windows .2 / ::2, iOS .3 / ::3 |
| Relay LAN | 203.0.113.64/26, 2001:db8:31:2::/64 | Сервер .65 / ::1, Windows .66 / ::2, iOS .67 / ::3 |
| DNS_PRIMARY / DNS_SECONDARY | REPLACE_* | Официальные адреса выбранного Cloudflare resolver |
| MTU | 1280 | Начальная величина, проверить бюджет overhead |

Каждому серверному экземпляру — отдельные ключи и согласованный с клиентами набор параметров AWG 3.1, каждому устройству и пути — отдельный private key, PSK и адрес. Не публикуйте индивидуальные протокольные параметры. Независимые профили не используют один private key одновременно на двух устройствах.

`examples/variables.json` — справочник плана, **не вход автоматического установщика**. Значения в остальных шаблонах меняются вручную согласованно. Изменив порт/подсеть, проверьте обе стороны Realm, профили, systemd и обе семьи firewall. Храните единственный закрытый inventory вне Git.

## Порядок допуска

Административный SSH и консоль работают независимо от VPN; свободные порты и непересекающиеся подсети подтверждены. DNS/HTTPS/IPv6 между VPS проверены. До запуска AWG должны быть установлены собственные ограничивающие правила. Default route хоста и глобальные политики firewall не меняются. Защитные ограничения нельзя выводить из предположения, что библиотека слушает только одно семейство адресов: проверить `ss` и заблокировать ненужное семейство.
