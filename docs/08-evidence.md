# 8. Происхождение и пределы доказательств

База этого изменения: `e862c47900559767da195adf745528def38c48b5` (main). [Первоначальный README](https://github.com/kaa224/amnezia_ip_v6/blob/e862c47900559767da195adf745528def38c48b5/README.md) сохранен Git без переписывания истории. Новый README — оглавление, исторические выводы ниже не являются новыми измерениями.

Источники: исходный README, предыдущие закрытые отчеты о развертывании 3.1 и узком исправлении публичного HTTPS; read-only просмотр текущих служебных скриптов; официальные pinned исходники AWG Go, tools и Realm. Закрытые конфиги, профили и индивидуальные параметры не копировались в проект. Конкретные адреса, названия внутренних приложений, серверные aliases, логи и детали инфраструктуры исключены.

## Исторические факты (20.11.2026)

- Два независимых userspace AWG 3.1 и фиксированный IPv6 Realm backend были развернуты и проверены временными peers: handshake, DNS Cloudflare, внешний HTTPS, IPv4 выхода, блокировка IPv6 и частных сетей.
- Отдельная проблема публичного HTTPS выходного VPS оказалась INPUT DROP: целевой public IP локален хосту, поэтому FORWARD исключение не помогает. Узкое исключение TCP443 исправило тесты Direct/Relay; 80 не требовался.
- Предыдущие отчеты подтверждали удаление тестовых peers/процессов и сохранность ранее работающих служб. Нагрузочный тест и reboot не проводились.
- В исходном README записано подтверждение нового подключения на Windows владельцем. Это не полный набор leak-тестов всех четырех профилей. Результаты IP/DNS/WebRTC прежнего AWG 2.0 нельзя переносить на 3.1.
- Старый AWG 2.0 сохранялся до отдельного подтверждения удаления; эта задача его не изменяет.

Read-only просмотр текущего firewall выявил отличие от исторического отчета в политике доступа к управлению. Оно **не переносится**: шаблоны проекта по умолчанию блокируют управление с VPN. Реальные службы/правила не исправлялись и не перезапускались. Это не аудит всей действующей инфраструктуры.

## Что проверяется в этом репозитории

Локальные tests проверяют структуру, placeholders, адресные диапазоны примеров, ключевые ограничения firewall, подготовку закрытых копий, отсутствие сетевых/служебных действий в scripts и относительные ссылки. Это статическая проверка, не семантическое доказательство Linux firewall и не E2E VPN.

Полное чистое развертывание шаблонов, `systemd-analyze verify` на целевой ОС, kernel `iptables-restore --test`, реальный импорт на Windows/iOS, внешняя доступность frontend, все отрицательные проверки, DNS/IPv6/WebRTC при обрыве, restart/reboot и MTU для выбранных параметров остаются обязательными следующими проверками. Доступный контейнер не имеет полного host systemd/netfilter/toolchain; привилегированный сетевой стенд в этой задаче не создавался.

Ограничение воспроизводимости: ключи и индивидуальные протокольные значения намеренно не поставляются, firewall persistence templates требуют адаптации к менеджеру конкретного VPS, поэтому клонирование репозитория не равнозначно готовой установке одной командой.
